# Помощники публикации

Используй после извлечения оригинала и подготовки перевода. Команды запускаются из корня репозитория; нужны Node.js 22 и установленные зависимости проекта. Сборка не нужна. Читать исходный код скриптов при обычной публикации не требуется.

Вход — JSON-файл вне публикуемого контента либо `-` и JSON через стандартный ввод. Последним аргументом можно передать другой корень репозитория для проверки на временных данных. Вывод — компактный JSON, ошибки дают ненулевой код завершения.

## Изображения

Выбери содержательные изображения и наиболее качественные исходные URL, затем выполни:

```text
node .agents/skills/translate-publish-article/scripts/download-images.mjs <images.json>
```

```json
{
  "slug": "article-slug",
  "cacheDir": "C:/path/to/task-cache",
  "images": ["https://example.com/image.png", "https://example.com/diagram.webp"],
  "coverUrl": "https://example.com/image.png"
}
```

- `images` перечисляются в порядке появления; одинаковый URL скачивается один раз за вызов.
- `coverUrl` необязателен и должен входить в `images`. Байты копируются в обложку без повторной загрузки.
- Формат определяется по содержимому через `sharp`; проверяются размеры, MIME ответа и соответствие расширения. Поддерживаются JPEG, PNG, GIF, WebP, AVIF, SVG и TIFF без преобразования.
- Имена — `<slug>-1.<ext>` и далее; результат содержит локальные URL и путь обложки.
- Запрос ограничен 30 секундами и 30 МиБ; необязательный `maxBytes` изменяет ограничение размера. Автоматических повторов нет.
- Все загрузки и конфликты проверяются до записи. Совпадающий существующий файл сохраняется, различающееся содержимое вызывает ошибку.
- При некорректном MIME проверь источник или выбери другой исходный URL. Неподдерживаемый формат требует отдельного решения.

Качество исходника, перевод подписей и alt-текста проверь самостоятельно. Используй `cacheDir` текущей задачи по [инструкции кеша](source-cache.md): повторный вызов получает байты из кеша. `refresh: true` явно обновляет загрузку; без `cacheDir` сохраняется режим без кеша.

## Статья, ссылки и реестры

Подготовь MDX и манифест:

```json
{
  "article": "src/content/posts/translations/article-slug.mdx",
  "canonicalUrl": "https://example.com/article",
  "originalTitle": "Exact original title",
  "date": "2026-09-20",
  "category": "translations",
  "verifiedAliases": [],
  "excludeExternal": []
}
```

`date` заполни текущей датой публикации, `category` — выбранной категорией. `verifiedAliases` имеет тот же формат, что у помощника выборки: только проверенные адреса и непустое `evidence`; **последним URL каждой группы укажи canonical URL**.

Если оставшаяся внешняя ссылка несодержательна (например, профиль автора), добавь в `excludeExternal` объект `{"url":"https://example.com/author","reason":"Профиль автора"}`. Исключение должно соответствовать ссылке, реально оставшейся в статье, и иметь обоснование. Помощник не определяет содержательность автоматически.

```text
node .agents/skills/translate-publish-article/scripts/publish-article.mjs validate <publication.json>
node .agents/skills/translate-publish-article/scripts/publish-article.mjs preview <publication.json>
node .agents/skills/translate-publish-article/scripts/publish-article.mjs apply <publication.json>
node .agents/skills/translate-publish-article/scripts/publish-article.mjs check <publication.json>
```

Выполняй эти этапы последовательно:

1. `validate` проверяет текущую схему `posts` из `src/content/config.ts`, поля перевода, канонические теги, дату и категорию из манифеста, ссылку на оригинал, синтаксис MDX, локальные изображения и обложку, MIME/расширения, внутренние ссылки `/posts/…` и якоря заголовков. Компилируется только тело MDX, сайт не собирается. Поле `image()` проверяется как строка с отдельной проверкой файла. Описание — до 400 символов вместе с префиксом, без минимальной длины.
2. `preview` без записи рассчитывает изменения и проверяет конечную статью. Изучи список файлов, количество замен, список старых статей и предупреждения. Исправь ошибки. Дополнительное подтверждение пользователя для уже разрешённой публикации не требуется.
3. `apply` заново рассчитывает изменения и записывает их. Меняет ссылки новой статьи на найденные переводы, обновляет обратные ссылки в старых статьях, добавляет строку перевода, обновляет реестр внешних ссылок, сортирует записи. Конфликтующий перевод или дубликаты в реестре переводов вызывают ошибку до записи. Одинаковые нормализованные URL и повторяющиеся пути внешнего реестра объединяются.
4. `check` повторяет расчёт без записи. Успех означает, что статья проходит проверки и повторное применение не требует изменений.

Замены сохраняют подпись и атрибут title ссылки. Якорь переносится только при наличии соответствующего заголовка в переводе. Обязательная ссылка «Оригинал», код и изображения не заменяются. Ссылочная текстовая ссылка преобразуется отдельно от общего определения, которое может использовать изображение. В реестр попадают внешние ссылки, кроме оригинала, собственного сайта и `excludeExternal`.

## Границы автоматизации

- Смысл и полнота перевода, терминология, уместность тегов, качество иллюстраций и содержательность ссылок проверяются отдельно.
- HTTP-доступность всех внешних ссылок и произвольные перенаправления автоматически не проверяются. Передавай подтверждённые aliases по правилам выборки реестров.
- JSX, импорты и MDX-выражения требуют ручной обработки; помощник сообщает об этом. Старые статьи с такими конструкциями автоматически не изменяются.
- Якоря определяются по Markdown-заголовкам с `github-slugger`. Особые HTML-якоря и компоненты проверяй вручную.
- Поиск дублей по slug и оригиналу вне реестра остаётся отдельным шагом. Все публикации помощник не сканирует.
- Пути проверяются на выход за пределы репозитория, включая символические ссылки. Перед записью проверяется, что запланированные файлы не изменились.
- Запись нескольких файлов не является единой транзакцией. При ошибке отчёт перечислит уже записанные файлы; исправь причину и повтори `preview`, `apply`, `check`, сохраняя пользовательские изменения.
- Неожиданный формат реестра вызывает ошибку. Обработай нужные записи вручную, сохранив неизвестное содержимое; целиком реестры в контекст не выводи.

После изменения помощников запускай:

```text
node --test .agents/skills/translate-publish-article/scripts/lookup-registries.test.mjs .agents/skills/translate-publish-article/scripts/publication.test.mjs .agents/skills/translate-publish-article/scripts/source-cache.test.mjs
```

Тесты используют временные файлы и подготовленные ответы загрузки изображений; реальные реестры только читаются. При обычной публикации повторять тесты помощников не нужно.
